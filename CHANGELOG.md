# Release Notes

## [Unreleased](https://github.com/made-foryou/made-cms-package/compare/v0.1.0...1.x)

### Added

- The card "Hoe je link gedeeld wordt" on the screen of a page (issue #182, design 23 and 24), below "Hoe Google hem ziet": a shared link as WhatsApp, LinkedIn or Facebook shows it (the image that is shared in the shape 1,91 : 1, the domain, and the title and the description from the card of Google, which it follows while the editor types there), and the share image of the page with its name, size, folder and alt text. "Kiezen uit media" opens the picker ("voor Afbeelding in Hoe je link gedeeld wordt · aanbevolen 1200 × 630 px"), "Uploaden" uploads one photo and hands it to the crop step for its alt text, "Bijsnijden" crops the chosen photo and the cross takes it away. It warns without stopping a save: a photo below 600 × 315, another shape than 1,91 : 1 (how much falls off, dimmed in the small image), a missing alt text (with a link to Media for whoever opens it), the default image of the site or no image at all, and a file a link cannot show. It saves on its own with "Opslaan" ("Niet opgeslagen", "Je kunt opslaan zodra de upload klaar is", "Opgeslagen"), also for a page Google may not show. The screen of a page now loads `upload.js`, `crop.js`, `media.js` and `share.js`; `cms.js` tells every change of the card of Google as `made-cms:meta {title, description}`. Hosts that published `lang/vendor/made-cms-package` add the keys `pages.show.share.*`, `pages.errors.share_image_*` and `media.places.share_image`.
- `MeasureShareImage::run($width, $height)` measures an image against what a shared link shows of it (`ShareImageFit`): too small below 600 × 315, and how much of another shape than 1200 × 630 (1,91 : 1) a link cuts away in its middle and where (`cut` in percent, `axis` `y` for the top and the bottom, `x` for the sides). It never refuses anything; the card "Hoe je link gedeeld wordt" warns with it.
- Open Graph for a shared link to a page (issue #182): `<x-made-cms::meta :page="$page" />` also writes `og:type` (`website`), `og:site_name`, `og:title` and `og:description` (the title and the description in Google), `og:url` (the canonical address), `og:image` with `og:image:width`, `og:image:height` and `og:image:alt`, and `twitter:card` (`summary_large_image` with an image, else `summary`), also for a page Google may not show. `PageMeta` has `image` (`ShareImage`: `{url, width, height, alt}` or `null`) and `siteName`, and `toArray()` gives them as `image` and `site_name` for Inertia, Vue or React.
- `DescribeShareImage::run($page)` gives the image of a shared link (`ShareImageDescription`): the share image of the page as the photo the site shows, absolute from the url of the media disk or `app.url`, with its size and alt text; else the default of the site from the new config `meta.share_image` (`url`, `width`, `height`, `alt`; env `MADE_CMS_SHARE_IMAGE`); else none. A file that is gone, no image or an svg falls back and says why, never with an error. `Support\Site::absolute($url)` gives an address an app can open from anywhere, or null.
- `SetPageShareImage::run($page, $mediaId)` with the `PageShareImageChanged` event gives a page the image a shared link to it shows, or none of its own (`null`), at once and outside the draft, with the place of the file in the media usage in the same transaction (issue #182). It refuses a file that is gone, no image or an svg (`ShareImageRefused` with a `ShareImageRefusal`: apps show a photo with a link). `PUT made-cms/pages/{page}/share-image` (`share_image`, the id of a file or empty) runs it for the card "Hoe je link gedeeld wordt" and goes back to `#made-cms-share`.
- A share image counts as a place of its file (issue #182): `SyncMediaUsage` gives it a row of the page itself, so the media library keeps the file ("Verwijderen" stays off), finds it by the title of the page, and names the place "Deelafbeelding" under the page, without a note about the draft and with a link to the card on the screen of the page when the page holds the file nowhere else. `MediaPlace` says `ofPage()` and `shownOnSite()`; a new version of a file a published page shares says that the site shows it. `made-cms:media-usage` builds the place too.
- The migration `add_share_image_to_cms_pages_table` gives `cms_pages` the column `share_image_id` (issue #182): the file of the media library a shared link to the page shows, null for the pages that are there; a foreign key keeps a file a page shares in the library. A host that ran the migrations before publishes them again (`php artisan vendor:publish --tag="made-cms-package-migrations"`) and runs `php artisan migrate`.
- The sitemap and robots.txt of the site (issue #89): `Route::madeCms()` now also serves `sitemap.xml` of its route group and, in a group without a prefix, `robots.txt`, before the pages and without a redirect, a launcher or a login. The sitemap lists every published page visitors see whose "Mag Google hem tonen" and "Staat in de sitemap" are on, with the address absolute from `app.url` and the prefix of the group (as its canonical address) and `lastmod` the moment it was last published, as a W3C date; no `priority` or `changefreq`. It answers `application/xml; charset=UTF-8` with `Last-Modified` (and a 304 to `If-Modified-Since`). A page without an address, a page a Disallow rule for `*` or Googlebot keeps away, and the addresses after 50,000 or 50 MB are left out and stored as errors. robots.txt lets every robot in, writes the rules of the developer per robot with a comment that says who set them, and names the sitemap of every route group. A route the site has at `sitemap.xml` or `robots.txt` above `Route::madeCms()` stays its own. **The host deletes `public/sitemap.xml` and `public/robots.txt`**: the web server serves them before Laravel.
- The sitemap is built again after every change of a page that can change it (`PagePublished`, `PageUpdated`, `PageMoved`, `PageDeleted`, `PageRestored`, `PageVisibilityChanged`, `PageMetaUpdated`, listener `RebuildSitemaps`), once the answer is sent (`defer()`), once per request; a sitemap that would be the same is not stored again. The package puts `InvokeDeferredCallbacks` in the global middleware of a kernel that lacks it. `php artisan made-cms:sitemap` builds them by hand, for instance after an import.
- The migration `create_cms_sitemaps_table` stores the last 10 sitemaps of each route group (`Content\Models\Sitemap`, `SitemapBuilder`: the xml, the number of addresses, the errors, the cause with the page or editor, the moment), so the sitemap survives a deploy and every server serves the same one. A host that ran the migrations before publishes them again (`php artisan vendor:publish --tag="made-cms-package-migrations"`) and runs `php artisan migrate`.
- Config `sitemap.robots`: the Disallow rules of the developer, the paths per user agent (`['*' => ['/api/'], 'Googlebot' => ['/zoeken$']]`), with `*` and `$` as Google reads them. A value robots.txt cannot hold (no text, empty, a line break) is left out, so robots.txt never fails.
- Reading and building: `BuildSitemap::run($prefix, SitemapReason)`, `BuildSitemaps::run(SitemapReason)` (every route group, `BuiltSitemap`), `OpenSitemap::run($prefix)` (the stored one, or built at the first request), `MakeRobotsTxt::run()`, `ListRobotsRules::run()`, and `CheckPublicSiteFiles::run($prefix)`, which tells whether `public/sitemap.xml` (when it changed, its addresses, how many pages of the sitemap of the CMS it misses) or `public/robots.txt` (whether it names the sitemap of the CMS) goes first. Sources of the sitemap implement `Content\Sitemap\SitemapSource` (`SitemapSources`, the pages now); `PageBuilder::indexable()` and `inSitemap()`. Texts `sitemap.robots.*` and `console.sitemap.*`.

A list replaces the stored list, but an item with the `id` of a stored item keeps the fields it leaves out. The merged values are validated as a whole, so a field that was not passed can still be refused; `StripUpdated` is unchanged.
- Every item of an `Items` field has a fixed `id` (a uuid), given when the strip is stored by `AddStrip` or `UpdateStrip` and rendered as the first key of every item (`null` for an item stored without one). An item may no longer have a field named `id`: a strip type that has one renames it, or the catalogue throws `InvalidStripType`.

- `cms_pages` gains `parent_id` (the page it lies under), `position` (its place among its siblings), `in_menu` and `deleted_at`: deleting a page is a soft delete, which frees its address and keeps its content for 30 days. A host that already ran the `cms_pages` migration runs it again (`migrate:fresh`).
- The CMS menu lists under "Je site" the overview "Alle pagina’s" followed by every page in the menu, indented under its parent; the pages screen is no longer listed as coming.
- `Shell::respond()` and `Menu::groups()` take the page tree and the open page as optional arguments; menu items carry their `depth`.
- A strip that links to a deleted page renders no url, like a link to a draft, and a draft with that link is refused by `PublishPage` until the link changes or the page is restored.

- Requires PHP 8.4 or newer; PHP 8.3 is no longer supported. A host on PHP 8.3 upgrades PHP before it updates the package.
- `cms_pages.slug` is no longer unique: the address of a page is unique in `cms_routes`, so pages under different parents can share a slug. A host that already ran the `cms_pages` migration runs it again (`migrate:fresh`) or drops the unique index on `slug` itself.
- `PublishPage` publishes the draft: its strips become the published strips and the draft is cleared, also on a page that is already published (`published_at` is the last publication). It refuses a draft with a strip that breaks its strip type, hidden strips included, with a `ValidationException` keyed by `strips.<strip id>.<field>`, and still throws `PageAlreadyPublished` for a published page without a draft. A host that already ran the `cms_pages` migration runs it again (`migrate:fresh`) or adds the `strips` (json) and `draft_strips` (json, nullable) columns itself.

- Screen labels moved to `screens.label.<screen>` in the translation files, next to the new `screens.group.<group>`; a host that published the translations republishes them (`made-cms-package-lang`).
- `NewEditor` takes the editor's `roles` (at least one) and `made-cms:editor` gains the `--role` option; without it the command asks for the roles.
- The default `routes.prefix` is now `made-cms` (was `cms`): every CMS route, the mail link and the launcher assets moved to `/made-cms/...`.
- `IssueLoginCode::run()` takes a `LoginCodeRequest` (address, browser binding, page to return to) and returns the link token too; `cms_login_codes` gains `attempts`, `session_hash`, `link_hash` and `return_to`.
- `Route::madeCms()` and `ResolvePage` redirect another form of the address of a page to the canonical one: a `GET` or `HEAD` for `/Over-Ons`, `/over-ons/` or `//over-ons` answers a `301` to `/over-ons`, under the prefix of the route group and with the query string, instead of serving the page with a 200. An address without a page still answers 404; a `POST` is never redirected.
- `RenderStrips::run($page)` renders the draft, or the published strips without a draft, in the edit mode; outside it nothing changes.
- `LauncherVisitor` gains `editing`; `ShowLauncher` hides the launcher in the edit mode.
- `ShowLauncher::run()` returns a `LauncherView` (hidden, tile or edit bar) instead of a boolean; `LauncherVisitor` gains the logged-in `editor`.
- After too many login attempts the launcher says a wait of more than 90 seconds in minutes ("Probeer het over 57 minuten opnieuw"), with the new text `launcher.errors.throttled_minutes`; `retry_after` stays in seconds.

### Removed

- The texts `cms.edit.choose` and `cms.edit.hidden_strips`; a host that published the translations of the package can remove them.
- Scaffold placeholders: the `CmsPackage` class and facade, the placeholder command, migration, view, translation and config key.

### Fixed

- Saving a page whose address gets longer than 255 characters (the length of `cms_routes.path`), also the address of a page under it after a new slug or a move, and restoring a page whose parent got a longer address meanwhile, is refused with a message instead of a server error on MySQL and PostgreSQL. `CreatePage`, `UpdatePage`, `MovePage`, `RestorePage` and `RewritePagePaths` throw `PagePathTooLong` (`PagePath::MAX_LENGTH`, `PagePath::fits()`); `RewritePagePaths` works out every address before it writes one. A slug holds at most 120 characters once it is made, also one made from the name (a letter such as щ or ß grows in it): `PageSlug::fromString()` throws `PageSlugTooLong` (`PageSlug::MAX_LENGTH`). Texts `pages.errors.slug_long`, `path_long`, `move_path_long` and `restore_path_long`; a host that published the translations adds them.
- An address of the site with a control character (a NUL byte, `%00`) or bytes that are no UTF-8 is a 404 without a lookup, instead of a server error on PostgreSQL: `PagePath::fromString()` throws `InvalidPagePath`.
- Two editors who give a page the same address at the same moment, or restore the same page twice, no longer get a server error: the check that an address is free runs inside the transaction that writes it, and the unique index of `cms_routes.path` refusing it is `PagePathTaken` too, also for a page under a moved page that lands on an address made outside the tree. `RestorePage` reads the page again with its row locked (`PageNotDeleted`). A page moved under a page that went under it at the same moment is refused (`CircularPageMove`), and so is a parent deleted meanwhile (`ParentPageDeleted`): `CheckPageParent` runs in the transaction of `UpdatePage` and `MovePage` and reads the parent and every page above it with their rows locked.
- `CreateMediaFolder` refuses a name another folder got at the same moment inside a savepoint of its own, so on PostgreSQL a transaction of the host around it stays usable; PostgreSQL aborts a whole transaction on a refused statement.
- Publishing the migrations again (`php artisan vendor:publish --tag="made-cms-package-migrations"`) no longer adds every migration a second time under a new date, which `migrate` then ran again and stopped on a table that exists. A migration the host has, under any date, is skipped (`--force` overwrites it where it is); only a migration the host does not have yet is published, dated after the ones it ran. A host that published twice before this fix deletes the newer copy of each migration it has twice before it migrates.
- A red button that deletes ("Ja, verwijder …" in the media library, deleting a page) has dark text in the dark colours, so it stands out on its light red (4.8:1 instead of 2.8:1).
- The edit shell no longer sends the editor back to the top of the site when its frame reloads after a change, a strip that moved or a publication, on a site rendered in the browser (Inertia, React without ssr): the frame holds the place the editor was looking at while the site grows to it and when it scrolls by itself (Inertia puts back a place it remembered, smoothly), until the editor scrolls. A strip that was added or moved and lies outside that view comes into view once the site shows it.
- Cleaning rich text no longer cuts it off at 65,535 bytes; the validation still allows at most 65,535 characters.
- Rich text nested deeper than 100 levels no longer crashes PHP when it is stored or rendered: markup beyond that depth keeps only its text.
- Changes to the draft made at the same time no longer get lost: two strips saved at once in the side panel, the opbouw moving or removing a strip while the panel saves another, two editors on one page. Every strip Action, `PublishPage` and `DiscardDraft` reads the page again in a transaction with its row locked (`ChangeDraft`), so the next change waits and starts from what the previous one stored; publishing and discarding see the draft as it was last stored. A page deleted in between throws `ModelNotFoundException` (404).
- A draft that no longer changes anything (a change undone, a strip hidden and shown again, a strip removed and put back) falls away: `draft_strips` is `null` again, the overview of the pages no longer shows a draft and the bar says "Geen wijzigingen". `UpdateStrip` then answers the strip as the published page holds it, with the ids of its items.
- `PublishPage` checks a field that a strip does not hold yet (a field its type got later) as its default, as the site renders it, instead of refusing it as empty. `UpdateStrip`, `RestoreStrip` and `PublishPage` check strip values in one place (`CheckStripValues`).

### Security

- Logging in finds an editor only by exactly the typed address, whatever the collation of the database. `EditorBuilder::firstWithEmail()` gives the editor of an address; `forEmail()` stays for whether an address is taken.
- A version of a file that waits to be put back after a replacement is private: the photo, its thumbnail or the file kept as it came in can no longer be opened by a visitor, so a file replaced because it should not be on the site is gone at once, not only after the next replacement. A CDN may keep a copy until its cache expires; purge it when a file must be gone everywhere at once.
- The original of a photo is written private: 0600 on a local disk, the ACL `private` on an S3 disk such as DigitalOcean Spaces. It holds the full size and the metadata of the camera (GPS too), and used to get the visibility of the disk, so on a public bucket anyone with its address, or a listing of the bucket, could open it. Only the app reads it, for the crop step and a crop. Originals stored before keep the visibility they got. On a local disk 0600 keeps out a web server that runs as another user than PHP; where both run as one user (Herd, `php artisan serve`), the name of 40 random characters protects it, as before.
- A password login no longer tells by its speed whether an address has an account. An unknown address and an account without a password used to make a hash and check it, twice the work of a wrong password; from bcrypt cost 12 that took longer than the timebox of 400 ms could hide. Now every path checks exactly one hash: the stand-in is made once with the current hash settings and kept in the cache (again when the settings change).
- Login codes are stored as a keyed hash (HMAC-SHA256 with the app key) instead of the password hasher. Asking for a code and checking one now take the same short time for every address, so the timebox of 400 ms hides whether a code was made, also with a slower password hasher. A code asked for before this update no longer works; ask for a new one.
- A new login code only replaces the earlier code of the same browser. Someone who keeps asking for codes for an editor's address in another browser no longer makes the code and the mail link of that editor stop working.
- The login rate limits count an IPv6 address per /64, so one connection can no longer get past a limit by taking another address from its own block. IPv4 addresses (also written as IPv6) still count one by one.
- The login rate limits also count per typed address, whatever the ip address: 10 login codes and 50 passwords an hour. Changing ip addresses no longer gives unlimited guesses or an unlimited stream of mails to one address. A known and an unknown address get the same answer. A browser that logged in with the address before (the `made_cms_editor` cookie) counts on its own, so someone who exhausts the limit cannot lock the editor out on their own device. The password login has a limiter of its own, `made-cms-package.password`; `made-cms-package.login` now covers checking a code and the mail link only.
- The code from the authenticator app and the recovery codes are also limited per editor, whatever the ip address: 10 tries an hour, next to 5 a minute per ip address. Someone who knows the password can no longer guess the second factor from ever new ip addresses. An editor who runs into the limit can still log in with a code by mail.
- Rich text is also cleaned when it is rendered, not only when it is stored. HTML that reached `strips` or `draft_strips` another way (a seeder, an import, a field that used to be another type) and the `default()` of a `RichText` field no longer reach visitors or the edit mode with scripts, event attributes or `javascript:` links. A stored rich text that is not a string renders as `null`.
- `DescribeStrip` hands the side panel the values as the package stores them, so rich text that reached the database another way reaches the panel cleaned (an item without an id gets one there). The panel only shows rich text on the site in the frame as the markup it builds itself, also when "Ongedaan maken" puts a value back.
- The link button of a rich text field reads an address as the browser does: `javascript:` with a tab or line break in it is refused, and so is an address starting with `//` (another site that looks like an address on the site).
- A link in rich text to an address starting with `//` loses its address when it is stored and when it is rendered, so it can no longer lead to another site while it looks like an address on the site.
- A `Link`, and the link of a `Button`, renders only an address the validation accepts: one that reached the database another way (a seeder, an import), such as `javascript:alert(1)` or `//example.com`, renders as `null`, so a button disappears. The validation also refuses an address starting with `/\`, which the browser reads as another site. The side panel no longer shows such an address on the site in the frame while the editor types.
