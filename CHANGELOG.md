# Release Notes

## [Unreleased](https://github.com/made-foryou/made-cms-package/compare/v0.1.0...1.x)

### Added

- Field type `Heading` (`Content\Strips\Fields\Heading`, `heading` in `describe()`): a text with its level, stored and rendered as `{"text": "…", "tag": "h2"}`. The level is `h1` to `h6`, or `span` for a text that is no heading for search engines. `Heading::make('kop')->tag('h1')` gives the level of the design (`h2` by default) and `->tags(['h1', 'h2'])` limits the levels to choose from (all seven by default). The text follows the rules of a `Text`; a level outside `tags()` is refused. A text stored before the field became a `Heading` (a former `Text`) counts as that text with the default level, so switching needs no migration: `UpdateStrip`, `PublishPage` and `RestoreStrip` check a stored value in its current form and `CompareDraft` counts no change for it. A level the developer later takes out of `tags()` counts as the default level too, so it never stops a publication. Without a text it renders as `null`, and at the default level it is stored as `null` too; another level stays, so a level chosen before the text is typed is kept. `default()` takes a text or `{text, tag}`. The catalogue throws `InvalidStripType` for a level that is no tag and for a default level outside `tags()`.
- Blade component `<x-made-cms::heading :heading="$strip->kop" field="kop" class="hero__titel" />` (`Http\Components\Heading`): renders a heading as the element of its level, `<h2 data-cms-field="kop" class="hero__titel">Welkom</h2>`, with the other attributes of the site and the text escaped; nothing without a text. In a list `field` names the field of the item. A level that is no heading tag renders as a `span`.
- The side panel edits the text of a heading (a group with the name of the field and its text); the heading keeps its level, or gets the default level of the field. Watching along patches the text while the element on the site is the element of its level; otherwise the frame reloads after the draft is saved. The opbouw and the rows of a list sum a heading up by its text.
- Dutch and English texts for headings (`strips.heading.*`): the label of the text, of the level and of every level ("H1" to "H6", "Geen kop").

- `GenerateStripTypes::run($scan)` writes a class for every strip type of a (reviewed) `ScanResult` into the strip types folder of the site (`strips.path` under `strips.namespace`, where the catalogue finds it), only at `APP_ENV=local` (else `NotLocalEnvironment`). A class reads as the developer would write it: the key, the label when the class name does not read as it, and the fields with what the scan knows (required, the most items seen as the max of a list, the options of a choice with a label to translate); it passes Pint unchanged. An image waits for the image field: it is left out with a comment in the class. It never overwrites: a type is skipped when the catalogue would refuse its definition, when the catalogue or the scan already has its key, or when the folder has its class, whatever the capitals. The answer (`GeneratedStripTypes`) lists the classes written (`GeneratedStripType`) and the types skipped with their reason (`SkippedStripType`, `StripTypeSkip`).
- Dutch and English texts for generating the strip types (`scan.generate.*`): the comment for a field left out, the reasons to skip a type and the counts.
- JSON endpoint `POST /made-cms/scan/strip-types` (`scan.strip-types.store`, behind `EnsureScanAccess`): takes a (reviewed) `ScanResult` and writes its strip types through `GenerateStripTypes`. It answers the classes written (`key`, `class`, `path` from the root of the site, `left_out`), the types skipped (`key`, `class`, `reason`, `label`, `detail`) and a `summary` ("6 striptypes geschreven, 2 overgeslagen"), never stored by a cache. A result of another version, without types or with a field it cannot read answers 422.
- `RecogniseDevice::run(new LoginStart($email, $device))` decides whether a device logged in with the typed address before. The greeting after the e-mail step and the login limits per address use it.
- `CheckScanAccess::run(new ScanVisit($editor))` decides whether the scan opens: only for an admin, and only at `APP_ENV=local`. The middleware `EnsureScanAccess` guards the routes of the scan with it, whatever its panel shows: a guest gets 401 (JSON) or the login page, anyone else 403. The scan has no `Screen` of its own.
- `ScanResult`, the form in which the scan of a site (epic #12, step 4) proposes strip types (`ScanType`, `ScanField`) and the content of every scanned page (`ScanPage`, `ScanStrip`), with the doubts of the scan per type and field (`ScanDoubt`). `RecognisedPage`, `RecognisedStrip` and `RecognisedField` hold what the scan read on one page (`ScanRole`: what an element is) until the pages are combined. Both read back what they write (`fromArray()`/`toArray()`).
- `RecognisePage::run(new ScannedPage($url, $html))` reads the rendered HTML of one page for the scan, deterministic and without any service. It finds the title of the page (a heading of its own in the content, else `<title>`) and its strips: the blocks of `main`, or without `main` the blocks under the site's own wrappers, without the header, the navigation, the footer, hidden elements and the elements of the CMS. Every strip has a selector that finds it in the document and in the browser, and a fingerprint of its structure without texts. In every strip it reads the fields with their values in the stored form: a heading as text, a paragraph as long text (a line per `br`), a block of paragraphs, a list of plain lines or a paragraph with a link as rich text, a link with a text of its own as a button, a link around a card, an image or nothing as a link, and an `img`, a `picture` or an inline background as an image `{url, alt}`. It passes forms, buttons of the interface, hidden texts and icons by, and doubts decorative images, background images and strips that hold a form. Two or more siblings in a row with the same tag and (nearly) the same structure are a list, with the fields of every item and its icons; a repeat inside an item becomes a long text with a line per element. The fingerprint does not count the items of a list, so strips of one type have the same fingerprint on every page.
- `CombinePageScans::run($pages)` combines what the scan read on the pages of a site into a `ScanResult`. Strips with the same fingerprint are one strip type, named after their id or a class that reads as a name (`over-ons`, `hero`), else after their place ("strook-3", with a doubt); fields are named after what they are ("kop", "tekst", "knop", numbered when the name comes back) in the language of the launcher. Fields line up by their place in every instance: a field one instance lacks is optional, a list proposes `min` 1 and the most items seen as `max`. Icons that differ per item of a list are a choice with their classes as options (`lucide-users` → `users`); a link with the same text in every item is a link of its own; a short label that every item shows the same ("Spelers") is left out, a longer text that every item shows the same is doubted.
- Dutch and English texts for the scan (`scan.*`): the generic names of strip types and fields, and an explanation of every doubt.

- The opbouw of a page in the side panel of the edit shell (design 11.6–11.13): without a chosen strip the panel lists every strip of the page in order, with its name, "Verborgen", a few words of its content and its number of fields. "+ Strook toevoegen" and an insert point between every two strips open the catalogue of the site (the strip types with their description and number of fields; a search field from 10 types), where one click places a new strip: the frame reloads with the strip chosen and its fields open, and a note says which required fields are still empty. A strip moves by dragging its grip, with ↑ and ↓ on the grip (Enter drops, Escape puts it back) or with the arrows next to its name once it is chosen. "Strook verwijderen" removes the chosen strip without asking; a notice at the top of the opbouw puts it back with "Ongedaan maken", with its content and in its place, for as long as the shell is open. A strip of a type the site no longer has is listed as "Niet op de site" and can only be removed. An empty page invites to add its first strip.

- JSON endpoints for the opbouw of the edit shell, for every editor who opens `Screen::Pages`: `GET /made-cms/pages/{page}/strips` (`pages.strips.index`) answers the strips of the working copy; `POST` to the same address (`pages.strips.store`, `{type, position}`) adds a strip through `AddStrip` (201); `PUT …/strips/{strip}/position` (`pages.strips.position`, `{position}`) moves it through `MoveStrip`; `DELETE …/strips/{strip}` (`pages.strips.destroy`) removes it through `RemoveStrip` and answers the removed strip as it was stored; `POST …/strips/{strip}/restore` (`pages.strips.restore`, `{type, visible, values, position}`) puts it back through `RestoreStrip` (201). A type that is not in the catalogue, a place outside the page or a strip that is already there answers 422 (`type`, `position`, `strip`), refused values 422 per field path, a strip that is not on the page 404, a guest 401. The answers are never stored by a cache.

- `RestoreStrip::run($page, $strip, $position)` puts a removed strip back in the draft with its own id, visibility and values, checked against its strip type, so the draft compares as if it had never been removed. A strip whose type left the catalogue comes back only with the values the published page holds. It dispatches `StripAdded` and throws `StripAlreadyOnPage`, `InvalidStripPosition`, `UnknownStripType` or a `ValidationException`.
- `StripType::summary($values)` and `Field::summary($value)`: a strip in a few words for the lists of the CMS, the first field with text (text, the first line of a long text, rich text without markup, the text of a button), else the titles of the items of a list; null when it holds no text yet.

- Watching along in the edit shell (#23): while the editor types, a field the view marks with `data-cms-field` (also inside `data-cms-items`) changes on the site in the frame without reloading it. That covers text, long text (with a `<br>` per line break when the view prints them with `nl2br`), rich text, the address of a link and the text and address of a button. A change the site cannot show that way reloads the frame after the draft is saved, at the same scroll position with the same strip chosen: a field without the attribute, a choice, an emptied field, an item added, removed or moved, a strip shown or hidden. React and Vue keep the patched text until the page renders again.
- Clicking a field on the site in the frame opens it in the side panel with the focus in it, inside its item when it lies in a list; clicking a list opens the list. The tab with the name of the strip still only chooses the strip.

- `CompareDraft::run($page)` with the `DraftChanges` data object: the strips the working copy adds, changes (values or visibility), removes or moves compared to the published strips, each strip once, with `count()` and whether the page can be published or its draft discarded. One strip dragged to another place is one change. Values are compared in the form the package stores them (a heading stored as text is its text with the default level, rich text is cleaned), a missing field as its default; the order of keys and the ids of list items do not count.
- JSON endpoints for the bar of the edit shell, for every editor who opens `Screen::Pages`: `GET /made-cms/pages/{page}/draft` (`pages.draft.show`) answers whether the page is live, how many strips the draft changes, whether it can be published or discarded and the texts of the bar ("Concept · 2 wijzigingen"); `POST …/publish` (`pages.publish`) puts the draft live through `PublishPage` and `DELETE …/draft` (`pages.draft.destroy`) throws it away through `DiscardDraft`, both answering 204. A draft with a strip that breaks its definition answers 422 keyed `strips.<strip id>.<field path>`, a live page without a draft 422 on `page`, a guest 401. The answers are never stored by a cache.

- Blade component `<x-made-cms::strips :page="$page" />` (`Made\CmsPackage\Http\Components\Strips`, component namespace `made-cms`): renders every strip of `RenderStrips` with the view of its strip type, `strips.{key}` or the name `view()` returns, and passes the strip as `$strip`. - `RenderStrips::run($page)`: the strips a visitor sees, ready to render in any stack. It returns `RenderedStrips` with a `RenderedStrip` per strip: the published version, in order, without hidden strips and without strips of a type that is no longer in the catalogue. `->toArray()` gives `[{id, type, ...fields}]` for an Inertia, Vue or React prop; in Blade a strip reads its values as properties (`$strip->kop`, `null` for an unknown name). - Rendered values of strips: `Field::render()` turns a stored value into what a view or a front-end component gets. - `Route::madeCms($responder)`: the site serves the CMS pages with one line, as the last of its web routes. ### Changed

- The package requires the PHP extension `dom` (`ext-dom`), which `symfony/html-sanitizer` already needed.
- The events of the content (`PageCreated`, `PageUpdated`, `PageMoved`, `PageDeleted`, `PageRestored`, `StripAdded`, `StripMoved`, `StripRemoved`, `StripUpdated`, `StripVisibilityChanged`, `DraftDiscarded` and `PagePublished`) implement `ShouldDispatchAfterCommit`: a listener runs once the transaction they are dispatched in commits, also a transaction of the host around an Action, and not at all when it rolls back.
- The side panel of the edit shell starts with the opbouw instead of "Klik een strook op de site om de inhoud te bewerken.", and hidden strips are chosen from the opbouw instead of a list of their own. "Strook n van m", in the panel and on the outlines in the frame, is the place of the strip in the opbouw: hidden strips and strips of a type the site no longer has count too.
- `RemoveStrip::run()` returns the removed `Strip` as it was stored (it returned nothing).
- `ListEditableStrips` lists every strip of the working copy, so the place of a strip in the list is the position the strip Actions take: a strip whose type left the catalogue is no longer left out but marked with `known: false`. `EditableStrip` has `known` and `summary` (`StripType::summary()`).
- `UpdateStrip` and `PublishPage` refuse strip values with the messages of the package in the language of the CMS (`StripType::messages()`, "Vul Kop in.") instead of the host's validation messages. A host that relied on its own `validation.*` lines for strips publishes the translations (`made-cms-package-lang`) and changes `strips.validation.*` there.

- `UpdateStrip::run($page, $stripId, $values)` merges the values with the stored values of the strip instead of replacing them: a field left out keeps its value instead of falling back to its default. To clear a field, pass it as `null` (or `[]` for a list); a host that relied on leaving fields out to reset them passes them explicitly. A list replaces the stored list, but an item with the `id` of a stored item keeps the fields it leaves out. The merged values are validated as a whole, so a field that was not passed can still be refused; `StripUpdated` is unchanged.
- Every item of an `Items` field has a fixed `id` (a uuid), given when the strip is stored by `AddStrip` or `UpdateStrip` and rendered as the first key of every item (`null` for an item stored without one). An item may no longer have a field named `id`: a strip type that has one renames it, or the catalogue throws `InvalidStripType`.

- `cms_pages` gains `parent_id` (the page it lies under), `position` (its place among its siblings), `in_menu` and `deleted_at`: deleting a page is a soft delete, which frees its address and keeps its content for 30 days. A host that already ran the `cms_pages` migration runs it again (`migrate:fresh`).
- The CMS menu lists under "Je site" the overview "Alle pagina’s" followed by every page in the menu, indented under its parent; the pages screen is no longer listed as coming.
- `Shell::respond()` and `Menu::groups()` take the page tree and the open page as optional arguments; menu items carry their `depth`.
- A strip that links to a deleted page renders no url, like a link to a draft, and a draft with that link is refused by `PublishPage` until the link changes or the page is restored.

- Requires PHP 8.4 or newer; PHP 8.3 is no longer supported. A host on PHP 8.3 upgrades PHP before it updates the package.
- `cms_pages.slug` is no longer unique: the address of a page is unique in `cms_routes`, so pages under different parents can share a slug. A host that already ran the `cms_pages` migration runs it again (`migrate:fresh`) or drops the unique index on `slug` itself.
- `PublishPage` publishes the draft: its strips become the published strips and the draft is cleared, also on a page that is already published (`published_at` is the last publication). It refuses a draft with a strip that breaks its strip type, hidden strips included, with a `ValidationException` keyed by `strips.<strip id>.<field>`, and still throws `PageAlreadyPublished` for a published page without a draft. A host that already ran the `cms_pages` migration runs it again (`migrate:fresh`) or adds the `strips` (json) and `draft_strips` (json, nullable) columns itself.

- Screen labels moved to `screens.label.<screen>` in the translation files, next to the new `screens.group.<group>`; a host that published the translations republishes them (`made-cms-package-lang`).
- `NewEditor` takes the editor's `roles` (at least one) and `made-cms:editor` gains the `--role` option; without it the command asks for the roles.
- The default `routes.prefix` is now `made-cms` (was `cms`): every CMS route, the mail link and the launcher assets moved to `/made-cms/...`.
- `IssueLoginCode::run()` takes a `LoginCodeRequest` (address, browser binding, page to return to) and returns the link token too; `cms_login_codes` gains `attempts`, `session_hash`, `link_hash` and `return_to`.
- `Route::madeCms()` and `ResolvePage` redirect another form of the address of a page to the canonical one: a `GET` or `HEAD` for `/Over-Ons`, `/over-ons/` or `//over-ons` answers a `301` to `/over-ons`, under the prefix of the route group and with the query string, instead of serving the page with a 200. An address without a page still answers 404; a `POST` is never redirected.
- `RenderStrips::run($page)` renders the draft, or the published strips without a draft, in the edit mode; outside it nothing changes.
- `LauncherVisitor` gains `editing`; `ShowLauncher` hides the launcher in the edit mode.
- `ShowLauncher::run()` returns a `LauncherView` (hidden, tile or edit bar) instead of a boolean; `LauncherVisitor` gains the logged-in `editor`.
- After too many login attempts the launcher says a wait of more than 90 seconds in minutes ("Probeer het over 57 minuten opnieuw"), with the new text `launcher.errors.throttled_minutes`; `retry_after` stays in seconds.

### Removed

- The texts `cms.edit.choose` and `cms.edit.hidden_strips`; a host that published the translations of the package can remove them.
- Scaffold placeholders: the `CmsPackage` class and facade, the placeholder command, migration, view, translation and config key.

### Fixed

- Cleaning rich text no longer cuts it off at 65,535 bytes; the validation still allows at most 65,535 characters.
- Rich text nested deeper than 100 levels no longer crashes PHP when it is stored or rendered: markup beyond that depth keeps only its text.
- Changes to the draft made at the same time no longer get lost: two strips saved at once in the side panel, the opbouw moving or removing a strip while the panel saves another, two editors on one page. Every strip Action, `PublishPage` and `DiscardDraft` reads the page again in a transaction with its row locked (`ChangeDraft`), so the next change waits and starts from what the previous one stored; publishing and discarding see the draft as it was last stored. A page deleted in between throws `ModelNotFoundException` (404).
- A draft that no longer changes anything (a change undone, a strip hidden and shown again, a strip removed and put back) falls away: `draft_strips` is `null` again, the overview of the pages no longer shows a draft and the bar says "Geen wijzigingen". `UpdateStrip` then answers the strip as the published page holds it, with the ids of its items.
- `PublishPage` checks a field that a strip does not hold yet (a field its type got later) as its default, as the site renders it, instead of refusing it as empty. `UpdateStrip`, `RestoreStrip` and `PublishPage` check strip values in one place (`CheckStripValues`).

### Security

- A password login no longer tells by its speed whether an address has an account. An unknown address and an account without a password used to make a hash and check it, twice the work of a wrong password; from bcrypt cost 12 that took longer than the timebox of 400 ms could hide. Now every path checks exactly one hash: the stand-in is made once with the current hash settings and kept in the cache (again when the settings change).
- Login codes are stored as a keyed hash (HMAC-SHA256 with the app key) instead of the password hasher. Asking for a code and checking one now take the same short time for every address, so the timebox of 400 ms hides whether a code was made, also with a slower password hasher. A code asked for before this update no longer works; ask for a new one.
- A new login code only replaces the earlier code of the same browser. Someone who keeps asking for codes for an editor's address in another browser no longer makes the code and the mail link of that editor stop working.
- The login rate limits count an IPv6 address per /64, so one connection can no longer get past a limit by taking another address from its own block. IPv4 addresses (also written as IPv6) still count one by one.
- The login rate limits also count per typed address, whatever the ip address: 10 login codes and 50 passwords an hour. Changing ip addresses no longer gives unlimited guesses or an unlimited stream of mails to one address. A known and an unknown address get the same answer. A browser that logged in with the address before (the `made_cms_editor` cookie) counts on its own, so someone who exhausts the limit cannot lock the editor out on their own device. The password login has a limiter of its own, `made-cms-package.password`; `made-cms-package.login` now covers checking a code and the mail link only.
- The code from the authenticator app and the recovery codes are also limited per editor, whatever the ip address: 10 tries an hour, next to 5 a minute per ip address. Someone who knows the password can no longer guess the second factor from ever new ip addresses. An editor who runs into the limit can still log in with a code by mail.
- Rich text is also cleaned when it is rendered, not only when it is stored. HTML that reached `strips` or `draft_strips` another way (a seeder, an import, a field that used to be another type) and the `default()` of a `RichText` field no longer reach visitors or the edit mode with scripts, event attributes or `javascript:` links. A stored rich text that is not a string renders as `null`.
- `DescribeStrip` hands the side panel the values as the package stores them, so rich text that reached the database another way reaches the panel cleaned (an item without an id gets one there). The panel only shows rich text on the site in the frame as the markup it builds itself, also when "Ongedaan maken" puts a value back.
- The link button of a rich text field reads an address as the browser does: `javascript:` with a tab or line break in it is refused, and so is an address starting with `//` (another site that looks like an address on the site).
- A link in rich text to an address starting with `//` loses its address when it is stored and when it is rendered, so it can no longer lead to another site while it looks like an address on the site.
- A `Link`, and the link of a `Button`, renders only an address the validation accepts: one that reached the database another way (a seeder, an import), such as `javascript:alert(1)` or `//example.com`, renders as `null`, so a button disappears. The validation also refuses an address starting with `/\`, which the browser reads as another site. The side panel no longer shows such an address on the site in the frame while the editor types.
